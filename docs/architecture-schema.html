A deterministic state machine over a fixed 15-stage DAG, executed as a Temporal workflow. Proposer agents emit schema-validated artifacts; coding harnesses act only inside risk-classed git worktrees; humans hold configurable decision gates; a shared memory makes the system learn across runs. This page overlays what is built today on the architecture's canonical shape.

Deployment topology ARCHITECTURE §9

The dashboard backend (E-10) is a second deliberate exception: its in-process fleet poller and subscriber set are not durable state, but not a stateless shell either — a per-request fan-out costs N_clients × N_runs where one shared poller costs N_runs (ARCHITECTURE.md §8).

Brownfield mode & Cartographer architecture ARCHITECTURE §3.1 · FR-102 · E-84

In greenfield mode, the factory initiates from a clean worktree. In brownfield mode (E-84 / FR-102), the factory ingests an existing repository and projects contextual codebase models into prompt budgets before feature architecture and planning.

1. Intake & Triage Stage 0 · classify_repo

  • done Routing: Pure classify() rule + Temporal classify_repo activity inspects git tree (commit count, file tree, marker files).
  • done Routes to greenfield (0 commits / empty repo), brownfield (existing repo), or repair (maintenance backlog).
  • done Fail-Closed: Immediately aborts and fails closed if brownfield mode is specified on a repo that has nothing to map.

2. Cartographer Context Stage 2 · CodebaseMap

  • done Projection: Projects a deterministic CodebaseMap from 13 Tier 2 scan signals (entrypoints, call graph, framework detection, dependency topologies, exports/symbols).
  • done Budget Enforcement: Bounded serialization via render_for_prompt(budget_tokens) guarantees prompt budget ceilings for downstream proposers.
  • done Injected by reference into Clarifier, Architect, and Planner prompts.

3. Checked Delta Stage 6 · check_brownfield_delta

  • done Proposer Delta: Architect proposer emits affected_modules and a structured BrownfieldDelta (typed lists of added, modified, and removed paths).
  • done Git Grounding: Activity check_brownfield_delta verifies modified/removed paths exist in git tree and added paths do not collide.
  • done Retry & Gate: Allows 1 retry with validation feedback before failing closed.

Assessment workflow (EDCR) pipeline ARCHITECTURE §3.2 · FR-911–FR-916 · E-45–E-49

AssessmentWorkflow executes an enterprise-grade Evaluate / Discover / Comprehend / Remediate (EDCR) DAG: init → scan → discover → assess → report → generate → finish (E-45).

Scan Phase E-46 · 13 Pure Signals

  • done Deterministic Signals: 13 pure signal modules executed across 2 activity waves + S5 merge + SS2 inheritance.
  • done Cache Key: Purely memoized on (tree_hash, signal_version, rules_sha); byte-identical across input order.
  • done Computes AST structure, call graphs, frameworks, dependencies, committed Cobertura coverage (QS2), pipeline CI files (QS4), and SARIF security scans.

Capability Identity & Graphs E-47a · E-47b · E-47c

  • done Identity (E-47a): Stable BC-NNN surrogate keys, weighted-Jaccard similarity reattachment across audit runs, audited IdentityCorrection logs (src/sdlc/capability/).
  • done Coverage & Orphans (E-47b): Capability coverage floor with 3 orphan verdicts: infrastructure, attached, or dead (discover/attribution.py).
  • done L2 & Ownership (E-47c): 2-level capability decomposition (decompose()); entity ownership assignment (assign()) following declaration → writes → reads.

Discover Proposer & Grounding E-48 · agents/discover/

  • done Proposer: discover_proposer agent generates DiscoverProposals (capability, refinement, attribution).
  • done Quote & Path Verification: verify_discover_refs byte-verifies every evidence path and quote against the pinned commit via Profile.VERBATIM_BYTES (FR-914).
  • done Citation Guard: Strictly fails closed if evidence fabrication rate exceeds 0.10 (SC-7 enforcement).

Blueprints & Domain Model E-48 · discover/{blueprint,domain}.py

  • done Blueprint Comparison: Correlates discovered capabilities against standard industry reference architectures (BIAN, TM Forum, ACORD, HL7).
  • done Derived Domain Model: Deterministically derives typed entity relationships, boundary definitions, and ubiquitous language from capability and ownership mappings.
  • done Order-independent pure transformations feeding downstream Assess (E-49) and Report (E-52) phases.

Assess Phase — Deterministic Score E-49 plan 1 · risk/{severity,controls,factors,composites,build}.py

  • done UnifiedRiskMap baseline, no model in the loop: criticality derived, severity from a table, absence never a rating; PHASE_OWNER loses its ASSESS entry so the phase is measured.
  • done Composites with sentinels: five control families (two report not_collected by RD5 decision, not mirroring), factors with 1–3 drivers, partial propagating (RD3 — QA/unified composites partial every run), memoized on (map digest, rules_sha).

Risk Proposer, Judgment & System View E-49 plans 2–3 · agents/risk/ · risk/{prompt,apply,crosscap}.py

  • done Judgment layer: risk_agent proposer emits RiskProposal (STRIDE, vulnerability, control dispositions); apply_judgment degrades layer-scoped, never the baseline; verify_risk_refs byte-verifies quotes via the lifted assessment/verification.py (RD6); memo refuses degraded judgment under a proposer key (P2-D3).
  • done System view (plan 3): capability→capability projection over attribution.graph.edges, shared vulnerabilities on the path-excluded weakness class, bounded cascades from high-security-composite origins, trust-boundary + privilege-escalation candidates dispositioned by the proposer. Known limit: escalation chains are authentication-gated, not authorization-gated (RD5).

Failure modes §11

  • done Worker crash mid-harness-run → heartbeat timeout, retry from checkpoint.
  • done LLM/API outage → activity retry + backoff.
  • done Human absent at gate → reminder + fallback approver + escalation/expiry timers + per-gate on_timeout (FR-303, E-9).
  • done Fix loops exhausted → escalation gate (accept / retry-with-guidance / quarantine).
  • done Quarantined task → dependents blocked, clean failure.
  • partial Payload > limits → sessions claim-checked (ArtifactStore, E-38); diffs still inline, no runtime guard (FR-702).
  • done Hindsight down → empty snapshot (logged).
  • done Prompt edited mid-fleet → memoization hash invalidates affected stages only.

Agent board as a durable projectionADR-21

Landed (E-78, 2026-08-07). Project artifacts + task status are projected into a durable store (SQLite) so they are addressable and queryable while a run is in flight. authoritative_status (workflow-written, from real stage outcomes) vs status (agent-writable) keeps Temporal replay the source of truth — statistics read authoritative only.
