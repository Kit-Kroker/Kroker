Agents Schema & Architecture

17 roles total (14 proposers/helpers + 3 harness roles) · agents/<role>/ registry · loader: src/sdlc/agents/loader.py · runtime: src/sdlc/agents/roles.py · workflow callsites: src/sdlc/workflows/feature.py, src/sdlc/workflows/assessment.py · contract source-of-truth: src/sdlc/models.py · Verified 2026-08-17 against agents/registry.yaml + agents/ + benchmarks/

Every role is a folder. The folder name is the role name, the API surface, and the Temporal activity namespace. Three kinds: proposer agents emit typed Pydantic artifacts via Pydantic AI wrapped in TemporalAgent; harness roles drive a coding CLI (opencode run / claude -p / cursor-agent) in a worktree; research is a proposer with four sequential tools and a pure verifier. The registry is parsed, validated (incl. ADR-6 cross-family check), and built at worker boot — a misconfigured registry cannot start a worker.

Overview three kinds, one registry

Agents are configuration in agents/<role>/, not source code. Each folder carries an agent.yaml (kind, model, provider), and — for non-harness roles — instructions.md (the system prompt) and agent.py (a build(model, instructions, model_settings, …) -> Agent factory). The folder name is the role name; the role name is the registry key; the agent's own name attribute is its Temporal activity name.

Proposer 13 roles

Required (8): clarify, architect, planner, qa, reviewer, analyst, merge_verdict, devops_planner. One LLM call (via Pydantic AI) emitting a schema-validated Pydantic artifact. Never touch the repo, never call tools except architect (research tool). Wrapped in TemporalAgent so model calls offload to activities. Optional (4): research (FR-107, now fans out, off by default); deep_review (E-39) reads the scrubbed harness transcript, advisory, never gates; handoff (FR-805) extracts task-to-task claims from the scrubbed session; adversary (decorrelated second opinion) runs only on the approving path, off by default. Assessment (1): discover (E-48) brownfield capability discovery proposer for AssessmentWorkflow.

Harness 3 roles

dev, test, devops. Drive an autonomous coding CLI inside a git worktree. Each role maps to a DevTask.role literal. role_cfg.harness picks the adapter (claude / opencode / cursor). No prompt, no agent.py — the workflow assembles the prompt and calls run_coding_task.

Research 1 role

research (FR-107). Optional proposer with four sequential tools and a pure verifier. provider field is required. See research-stage-schema.html for the deep treatment; this page summarises its place among the other agents.

Tool modules under agents/research/tools/ are structurally validated by AST (filename stem == top-level function name; every parameter and return fully annotated) before anything is imported. def check_adr6_families(role_models):
    # The single ADR-6 family check, reused at boot (validate_registry)
    # and per run (validate_run_roles, for --role-model / benchmark arms).
    dev, rev = role_models["dev"], role_models["reviewer"]

    # 1. dev and reviewer FAMILIES must differ
    if model_family(dev) == model_family(rev):
        raise RegistryError("reviewer family equals dev family")

    # 2. optional deep_review must also differ from dev (E-39)
    dr = role_models.get("deep_review")
    if dr is not None and model_family(dr) == model_family(dev):
        raise RegistryError("deep_review family equals dev family")

def model_family(model: str) -> str:
    # 'anthropic:glm-5.2'  -> 'anthropic'
    # 'zai-coding-plan/glm-5.2' -> 'zai-coding-plan'
    return re.split(r"[:/]", model, maxsplit=1)[0].strip().lower()

The adversary clause (NEW) loader.py:222

def model_id(model: str) -> str:                       # loader.py:78
    # 'anthropic:glm-5.2'       -> 'glm-5.2'
    # 'zai-coding-plan/glm-5.2' -> 'glm-5.2'
    # model_family() answers "who serves it"; this answers "what is it".
    return re.split(r"[:/]", model, maxsplit=1)[-1].strip().lower()

def check_adversary_model(role_models):                # NEW, separate from check_adr6_families
    adv = role_models.get("adversary")
    if adv is None: return                              # no-op when the optional role is absent
    for other in ("dev", "reviewer"):
        peer = role_models.get(other)
        if peer is not None and model_id(adv) == model_id(peer):
            raise RegistryError("adversary is the same model as " + other)

The adversary constraint is model_id(adversary) ∉ {model_id(dev), model_id(reviewer)} — by model identity, not provider prefix. Two prefixes over the same weights decorrelate nothing.

OQ-A4: dev/reviewer nominal vs. substantive. The shipped registry runs dev (zai-coding-plan/glm-5.2) and reviewer (anthropic:glm-5.2) on the same glm-5.2 weights behind different provider prefixes. The existing check_adr6_families dev/reviewer clause is therefore satisfied nominally but void substantively for the shipped registry. It is deliberately left untouched so no benchmark baseline shifts; the adversary clause above is the new, stricter identity check that actually enforces decorrelation for the second-opinion lens.
Reviewer is a clean-context proposer by default (ADR-6/ADR-12). It receives orchestrator-assembled inputs only (frozen contract + materialized diff + test output), holds no tools, no repo, no worker session, and never resumes the developer's harness session. The doer has tools; the judge does not — so the judge cannot wander or be polluted. The one family member allowed to see how the diff was reached is the optional deep_review proposer (E-39, cfg.deep_review_enabled): it reads the scrubbed HarnessSession as data via claim-check, advises, and never gates; its family is held independent of dev by clause 2 above.

Why opencode runs with --pure --auto. --pure excludes auto-discovered plugins (otherwise the user's global superpowers plugin auto-activates its brainstorming skill on "creative work" and the non-interactive activity stalls waiting for an answer that never comes; the plugin: [] config does not exclude auto-discovered plugins). --auto mirrors claude's --permission-mode acceptEdits — without it every tool call blocks on a permission approval that never arrives and the diff comes back empty.

Commands must be self-contained. 13. adversary proposer · decorrelated second opinion · non-DAG lens

adversary activity: adversary_agent stage: adversary (non-DAG lens, approve path only) output: ReviewReport model: anthropic:claude-sonnet-4-6 enabled by: cfg.adversarial_review_enabled (off by default) files: agents/adversary/{agent.py, agent.yaml, instructions.md}

Decorrelated second opinion (spec pt.2). Runs ONLY when the primary reviewer approves — review_ok = review is None or review.approve — because a rejection is already bound for the fix loop, so the expensive failure mode is a false approve. Holds no tools, no repo, no session: it receives the same clean-context inputs as the reviewer (frozen contract assertions + materialized diff + test output) and emits the same ReviewReport contract, so findings merge into the fix loop with no new plumbing. Fail-open: a failed adversary call counts as agreement; the primary reviewer remains the sole designated blocking lens (deliberately asymmetric to E-38's fail-closed scrub).

On agreement vs. split workflows/feature.py

  • Agree (both approve): task proceeds on the success path.
  • Split (adversary rejects): attempt is treated as failed; _fix_loop_issues returns the UNION of both reviewers' findings to seed the retry.
  • Adversary call fails: fail-open → agreement; the run never blocks on the optional lens.

Decorrelation by model identity loader.py:222

The constraint is model_id(adversary) ∉ {model_id(dev), model_id(reviewer)} — by model identity, not provider prefix. A second opinion from the same weights is not a second opinion. See the ADR-6 section for the new check_adversary_model clause.

Ships as claude-sonnet-4-6. ARCHITECTURE §4 places adversarial instruction-following on that tier; claude-sonnet-4-6 is genuinely different weights from the glm-5.2 family that dev/reviewer run, so the model-identity check holds for the shipped registry. The lens is advisory and fail-open; it is never the sole blocking lens.
