Research Stage Schema & Architecture

FR-107 · wired in src/sdlc/workflows/feature.py:695 · spec: docs/superpowers/specs/2026-07-17-research-agent-grounded-briefs-design.md · contract source-of-truth: src/sdlc/models.py

The research stage is an optional, human-gated, off-by-default pre-clarify stage (FR-107). A single proposer agent consults four sequential tools against a per-run budget, emits a schema-validated ResearchBrief, and a pure verifier fails the stage closed if any “grounded” quote is not a verbatim substring of bytes fetched this run. The brief is not memoized; only its canonical digest feeds downstream content keys. Verified findings enter memory as leads, never as grounded claims — recall cannot restore grounded status without re-verification.

1. Where the stage plugs in DAG position

The 15-stage DAG runs intake → constitution → context* → research → {research gate} → clarify → {clarify gate} → architecture → …. context is brownfield-only; research runs only when cfg.research_enabled is on and the registry built a t_research agent (agents/research/ present).

Off by default, not memoized. A served memo would mean pages were not fetched this run, so a brief cannot be cached (feature.py:695 comment, spec finding 4). Only the canonical brief_digest() contributes to downstream content keys (spec finding 3).

2. The contract: ResearchBrief schema

Defined at src/sdlc/models.py:311. Field order is reasoning order (schema-guided reasoning, SGR): decompose → gather → what the bytes say → what I concluded → where sources disagree → what I could not answer → summary → ref → confidence. tests/test_research_models.py pins the order; a reorder is a regression.

# field type rule / meaning
1sub_questionslist[SubQuestion] Decompose the idea before gathering.
2sources_consultedlist[ConsultedSource] Assess the source, then attach a relevance tag (judgment before label).
3grounded_findingslist[GroundedFinding] quote BEFORE claim. Verbatim span actually in fetched bytes, then what it supports. Verified by verify_brief_activity.
4inferred_findingslist[InferredFinding] reasoning BEFORE claim. Anything concluded without a fetched quote. A recalled lead honestly belongs here, never in grounded.
5contradictionslist[Contradiction] Where sources disagree.
6gapslist[Gap] Sub-questions that could not be answered (e.g. budget exhausted before reaching them).
7summarystr Free-form prose summary.
8brief_refArtifactRef | None Claim-check to the full brief in the artifact store.
9confidencefloat ≥0, ≤1 Author self-score. Surfaces to the gate; calibration tracked at retro (SC-6).

The agent calls tools sequentially: recall_leads → web_search → fetch_page → quote from fetched bytes; read_repo is free-standing and uncharged. This is the human-authorised fallback after the 2026-07-17 decision to drop CodeMode (untestable under TemporalAgent via TestModel).

charge() deps.py:54

def charge(deps, *, search=0, fetch=0) -> None:
    b = deps.budget
    if search and b.searches + search > deps.max_searches:
        raise BudgetExceeded(f"search budget exhausted ({deps.max_searches} searches)")
    if fetch and b.fetches + fetch > deps.max_fetches:
        raise BudgetExceeded(f"fetch budget exhausted ({deps.max_fetches} fetches)")
    projected = b.cost_usd + search*SEARCH_COST_USD + fetch*FETCH_COST_USD
    if projected > deps.max_cost_usd:
        raise BudgetExceeded(f"cost budget exhausted (${deps.max_cost_usd:.2f})")
    b.searches += search
    b.fetches  += fetch
    b.cost_usd = projected
Known gap (accepted loss, 2026-07-17 human decision). deps.budget accumulates correctly for direct / test invocation and within a single non-temporal agent.run(). Under TemporalAgent each tool call is a separate activity that receives its own deserialised copy of deps, so mutations do not flow back — charge() never raises mid-run. Restoring real per-run enforcement needs a disk-persisted counter at runs/<run_id>/research/budget.json (deferred — Task 8 follow-up).

6. The verifier the heart of the stage

Pure verification of a ResearchBrief against bytes fetched this run, plus the canonical brief_digest(). No network, no provider — just page files and strings. Defined in src/sdlc/research/verify.py.

The rule

grounded means normalize(quote) is a substring of normalize(page_text) for the page fetched this run for that source_url. Every further loosening is a hole in the check — add none without a test proving the specific false-failure it fixes.

normalize() verify.py:36

_WS         = re.compile(r"\s+")
_APOSTROPHE = re.compile(r"['‘’`�]")   # straight, curly, backtick, U+FFFD

def normalize(text: str) -> str:
    # 1. drop apostrophe / quote-glyph noise (symmetric)
    # 2. collapse whitespace runs to one space
    # 3. strip ends
    return _WS.sub(" ", _APOSTROPHE.sub("", text)).strip()

Case is preserved; all other punctuation is preserved.

Provenance of the _APOSTROPHE carve-out. Cat-cafe-monitoring smoke run (2026-07-20): Tavily's PDF extractor decoded a source's curly apostrophe (U+2019) as U+FFFD (REPLACEMENT CHARACTER) — "owner�s phone" on the page, "owner's phone" in an otherwise word-for-word-verbatim quote. Not a model error; the byte was already lost upstream. Dropping apostrophe variants symmetrically on both sides closes that specific hole without weakening word-level matching.

    return hashlib.sha256(url.encode()).hexdigest() + ".txt"

def pages_dir(run_id: str) -> Path:

verify_brief() deterministic verify.py:59

class Violation(BaseModel):
    kind: "quote_not_found" | "source_never_fetched"
    source_url: str
    quote: str

def verify_brief(brief, run_id) -> list[Violation]:
    for f in brief.grounded_findings:
        page = pages_dir(run_id) / page_filename(f.source_url)
        if not page.is_file():
            yield Violation("source_never_fetched", f.source_url, f.quote)
            continue
        if normalize(f.quote) not in normalize(page.read_text("utf-8")):
            yield Violation("quote_not_found", f.source_url, f.quote)

Fail-closed semantics

The workflow treats a non-empty violations list as a hard stage failure: the stage status becomes rejected:research.grounding and the run returns that string (feature.py:735). This is not a ModelRetry: TemporalAgent silently drops @agent.output_validator (Task 1 finding A), so grounding is enforced as a post-run activity rather than an output validator.

Why verify_brief_activity returns rather than raises activity

temporalio's execute_activity wraps activity-raised exceptions in ActivityError(ApplicationError), which would prevent the workflow from catching a typed GroundingViolation. So the activity returns list[Violation] and the workflow inspects the result directly. A direct (non-activity) caller that prefers an exception interface can raise GroundingViolation(violations) from the returned list.

VERIFY_ACT temporal policy feature.py:86

VERIFY_ACT = dict(
    start_to_close_timeout = timedelta(minutes=1),
    retry_policy           = RetryPolicy(maximum_attempts=1),
)

One attempt, no retries: the check is a deterministic substring lookup — retrying cannot change the outcome.

brief_digest() verify.py:75

def brief_digest(brief) -> str:
    pairs = sorted((f.source_url, f.claim) for f in brief.grounded_findings)
    payload = json.dumps(pairs, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(payload.encode()).hexdigest()

The brief's contribution to downstream content_key: canonical hash of (source_url, claim) pairs. Prose, ordering, and confidence drop out; facts remain. Same facts → same digest → clarify's memo hits.

7. Memory contract leads, never grounded claims

Defined in src/sdlc/research/retain.py. Verified grounded findings only enter memory; nothing unverified can ever be retained, so recall can never launder a false claim into ground truth.

verified_findings_to_retain() retain.py:11

def verified_findings_to_retain(brief, run_id, bank="project:default") -> list[RetainItem]:
    bad = {(v.source_url, v.quote) for v in verify_brief(brief, run_id)}
    items = []
    for f in brief.grounded_findings:
        if (f.source_url, f.quote) in bad:
            continue                            # drop unverified
        items.append(RetainItem(
            kind    = MemoryKind.RESEARCH_FINDING,
            bank    = bank,
            text    = f"{f.claim} — {f.source_url}",
            metadata= {"stage": "research", "source_url": f.source_url},
        ))
    return items
Findings become leads, not grounded claims. A retained finding is a lead: a hint about where prior runs looked. On recall, the research agent sees them via recall_leads and must re-fetch to re-ground. This is enforced structurally, not by prompt: a recalled lead placed in grounded_findings fails source_never_fetched by construction.

8. Two entry points, one agent stage vs mid-run

One core (the research agent); two callers. Both draw down the same per-run budget.

1. Top-level stage workflow

feature.py:700 — runs once before clarify when cfg.research_enabled and t_research is not None. The workflow builds ResearchDeps, awaits t_research.run(idea_json, deps=deps).output, verifies, gates, retains, judges, records.

Tool calls fan out as Temporal activities.

2. Architect mid-run agent

toolset.py:10 — research_subquery(deps, question) runs the same research agent on one sub-question. Imported lazily so agents/architect/agent.py stays importable without constructing the research agent at import time.

Runs inside the architect's tool-call activity — pydantic-ai's TemporalAgent cannot fan the inner agent's tool calls out as further activities from there, so it falls back to plain in-process execution and deps.budget genuinely accumulates here.

Asymmetric budget behaviour between the two entry points. Because research_subquery runs in-process under the architect's activity, a raised BudgetExceeded is caught there and degrades to a brief with the shortfall recorded in gaps (matching ResearchConfig's documented contract). Leaving it uncaught would escape the activity's Temporal boundary as an uncapped ApplicationFailure retry storm.

11. Known gotchas & accepted losses maintainer notes

1. @agent.output_validator is silently dropped by TemporalAgent

Task 1 finding A. Grounding is therefore enforced as a post-run activity (verify_brief_activity) rather than via an output validator. The workflow inspects the returned violations list and fails the stage closed.

2. Budget counter is advisory-only under TemporalAgent

Each tool activity receives a fresh deserialised copy of deps, so charge() never raises mid-run in the temporalised path. Real per-run enforcement needs a disk-persisted counter (runs/<run_id>/research/budget.json) — deferred (Task 8 follow-up). The research_subquery path is exempt: it runs in-process under the architect's activity.

3. read_repo must refuse by returning a string, never by raising

A raised ValueError on an out-of-root path becomes a Temporal ApplicationFailure retried with no cap — observed hanging a greenfield run indefinitely. Return "[refusing to read outside the repo root: …]" instead; the model reads it and moves on. Same pattern as the missing-file branch.

4. verify_brief_activity returns, does not raise

execute_activity wraps activity-raised exceptions in ActivityError(ApplicationError), which would prevent the workflow from catching a typed GroundingViolation. The activity returns list[Violation]; the workflow decides. GroundingViolation exists only for direct (non-activity) callers.

5. CodeMode was the original mechanism — dropped 2026-07-17

The original design used CodeMode to collapse the tool fan-out into one run_code activity with a shared in-process budget counter. Task 1's spike proved CodeMode untestable via TestModel under TemporalAgent, so the human-authorised fallback ships plain sequential tools. The shared-counter guarantee is a Task 8 concern.

6. The stage is not memoized

A served memo would mean pages were not fetched this run, so a brief cannot be cached. Only the canonical brief_digest() feeds downstream content keys — the brief's prose is never part of the cache hash.

7. Recalled findings are LEADS, never grounded claims

Enforced structurally: verified_findings_to_retain() stores only verified findings as MemoryKind.RESEARCH_FINDING; a recalled lead placed in grounded_findings fails source_never_fetched by construction. Re-fetch to promote.
