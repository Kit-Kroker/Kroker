Research Stage Schema & Architecture

FR-107 · wired in src/sdlc/workflows/feature.py:1726 · fan-out activities in src/sdlc/research/stage.py · spec: docs/superpowers/specs/2026-08-04-research-fan-out-design.md · contract source-of-truth: src/sdlc/models.py · verified 2026-08-14 against src/sdlc/, agents/research/, benchmarks/

The research stage is an optional, human-gated, off-by-default pre-clarify stage (FR-107). Since the 2026-08-04 fan-out design it is no longer one agent turn: the workflow fans out — plan_research decomposes the idea into ≤max_sub_questions independent sub-questions, N parallel research_subquestion activities each run the plain research agent in-process against their own per-scope budget, and synthesize_brief merges the partial briefs (deterministic) then makes one model call over them. A pure verifier then flags any “grounded” quote that is not a verbatim substring of bytes fetched this run. The verifier is byte-exact (whitespace-normalized only); a failed brief records the stage as FAIL (retain + digest skipped) and the run continues on the idea alone — fail-and-continue, not a block (E-29, 2026-07-20). The brief is not memoized; only its canonical digest feeds downstream content keys. Verified findings enter memory as leads, never as grounded claims — recall cannot restore grounded status without re-verification.

1. Where the stage plugs in DAG position

The 15-stage DAG runs intake → constitution → context* → research → {research gate} → clarify → {clarify gate} → architecture → …. context is brownfield-only; research runs only when cfg.research_enabled is on and the registry built a t_research agent (agents/research/ present).

Off by default, not memoized. A served memo would mean pages were not fetched this run, so a brief cannot be cached (feature.py:1721 comment, spec finding 4). Only the canonical brief_digest() contributes to downstream content keys (spec finding 3).

2. The contract: ResearchBrief schema

Defined at src/sdlc/models.py:731. Field order is reasoning order (schema-guided reasoning, SGR): decompose → gather → what the bytes say → what I concluded → where sources disagree → what I could not answer → summary → ref → confidence. tests/test_research_models.py pins the order; a reorder is a regression.

1sub_questionslist[SubQuestion] Decompose the idea before gathering.
2sources_consultedlist[ConsultedSource] Assess the source, then attach a relevance tag (judgment before label).

3. Components & fan-out architecture plan → N sub-questions → synthesize

Two layers: assets (what you edit to change behaviour — prompt, registry entry, tool implementations) live under agents/research/; code (what makes assets work — fan-out activities, merge, budget, verifier, retain) lives under src/sdlc/research/. The workflow wiring in src/sdlc/workflows/feature.py is the only deterministic caller.

The fan-out: three activities, not one turn

The stage is now plan → N × sub-question (parallel) → synthesize, with a bounded refine round on GateOutcome.REVISE. All three activities live in src/sdlc/research/stage.py and are registered in worker.py. Every model call is activity-side — fan-out moved them out of _run_role's reach — so each return type carries a RoleUsage (E-33 amendment, §usage below).

One schema-constrained model call whose output type is a flat list of strings (_PlannerOutput, stage.py:26). Ids are assigned by us, not the model — sq-<offset+i> — so they stay stable and offsettable across refine rounds (round-2 ids never collide with round-1).   • Own per-scope budget. ResearchDeps.scope = sub.id (stage.py:208) plus the shared "run" ceiling via charge_scoped — one sub-question cannot drain the run.
  • Heartbeats on a timer (HEARTBEAT_INTERVAL_SECONDS = 15, stage.py:132); invariant interval < heartbeat_timeout < start_to_close.
  • Degrades on BudgetExceeded / UsageLimitExceeded — never re-raises (the persisted counter would retry into the same cap); shortfall recorded as a Gap (stage.py:171), siblings survive.
  • Handles CancelledError with a heartbeat on the way out.

Deterministic merge_briefs first (structure from code, research/merge.py), then one model call with a closed output type _SynthesisOutput{summary, contradictions, confidence} (stage.py:249). The model cannot author a grounded finding — there is no field for one.

Refine round REVISE feature.py:1821

bounded by max_refine_rounds

GateOutcome.REVISE no longer collapses to reject. 4. The tool layer charged, persisted, grounded

Each research_subquestion runs the research agent, which gathers via two routes: the plain budget-charged tools (recall_leads, read_repo), and — since 2026-07-29 — ExaSearch (web_search, get_page, deep_search via WrappedExaSearchToolset) plus the Harness run_code capability, injected selectively when provider == "exa". The old web_search.py / fetch_page.py source files are removed; ExaSearch replaces them. Whatever the route, every search/fetch is charged against the sub-question's persisted scope and every fetched page is written to pages/<sha>.txt so grounding verification still applies byte-for-byte.

ExaSearch + run_code (2026-07-29). WrappedExaSearchToolset routes Exa's tools through charge_scoped (1 search for web_search/deep_search, 1 fetch for get_page) and mirrors get_page text into the page cache via verify.write_page. run_code lets the agent orchestrate parallel calls from a script. charge() deps.py:63

def charge(deps, *, search=0, fetch=0) -> None:
    b = deps.budget
    if search and b.searches + search > deps.max_searches:
        raise BudgetExceeded(f"search budget exhausted ({deps.max_searches} searches)")
    if fetch and b.fetches + fetch > deps.max_fetches:
        raise BudgetExceeded(f"fetch budget exhausted ({deps.max_fetches} fetches)")
    projected = b.cost_usd + search*SEARCH_COST_USD + fetch*FETCH_COST_USD
    if projected > deps.max_cost_usd:
        raise BudgetExceeded(f"cost budget exhausted (${deps.max_cost_usd:.2f})")
    b.searches += search
    b.fetches  += fetch
    b.cost_usd = projected

6. The verifier the heart of the stage

The matching logic lives in src/sdlc/grounding.py (since E-43), exposed as a two-profile API: Profile.EXTRACTED_TEXT — third-party HTML/PDF extractor output, what research briefs cite — and Profile.VERBATIM_BYTES — committed code and stored transcripts, where ** and quote glyphs are content, not noise. src/sdlc/research/verify.py is now the research-stage wrapper around that API: it owns the page-cache lookup that decides which bytes each quote is checked against, delegates the substring check to quote_violation(..., Profile.EXTRACTED_TEXT, ...), and exposes the Temporal activity plus the canonical brief_digest(). No network, no provider — just page files and strings.

The rule

grounded means verify_quote(quote, page_text, Profile.EXTRACTED_TEXT) is true for the page fetched this run for that source_url — equivalently, normalize(quote, EXTRACTED_TEXT) is a substring of normalize(page_text, EXTRACTED_TEXT). The check itself lives in grounding.py; verify.py just supplies the bytes. Every further loosening is a hole in the check — add none without a test proving the specific false-failure it fixes.

Two profiles, deliberately not one grounding.py:32

class Profile(str, Enum):
    EXTRACTED_TEXT = "extracted_text"   # third-party extractor output (research)
    VERBATIM_BYTES = "verbatim_bytes"   # committed code, stored transcripts

One invariant, three byte-sources: pages fetched this run (research), stored harness transcripts (handoff, deep_review), and committed code at path@sha (first consumer: E-41's triage secrets signal, which re-verifies every emitted evidence quote against the pinned commit; an LLM-proposing assessment consumer is still owed — FR-914). EXTRACTED_TEXT carries the two loosenings a third-party extractor forces on us; VERBATIM_BYTES carries neither, because ** is Python's kwargs/exponent operator and quote glyphs are meaningful inside string literals — applying the extractor profile to code would silently weaken the check SC-7 rests on. The research stage always uses EXTRACTED_TEXT. Grounding is pure (stdlib + Pydantic only) and never decides consequences: it returns a verdict; the caller chooses whether to fail a stage, drop a claim, or fail closed.

normalize() grounding.py:57

# EXTRACTED_TEXT profile (research). Live in src/sdlc/grounding.py since E-43.
_WS         = re.compile(r"\s+")
_APOSTROPHE = re.compile(r"['‘’`�]")   # straight, curly, backtick, U+FFFD
_MD_BOLD    = re.compile(r"\*\*")       # literal markdown bold markers

def normalize(text: str, profile: Profile) -> str:
    if profile is Profile.EXTRACTED_TEXT:
        text = _MD_BOLD.sub("", _APOSTROPHE.sub("", text))  # extractor noise only
    return _WS.sub(" ", text).strip()                  # whitespace collapse, both profiles

Case is preserved; all other punctuation is preserved. The carve-outs apply only to Profile.EXTRACTED_TEXT (third-party extractor output); VERBATIM_BYTES (code / transcripts) keeps ** and quote glyphs as content.

Provenance of the _APOSTROPHE carve-out. Cat-cafe-monitoring smoke run (2026-07-20): Tavily's PDF extractor decoded a source's curly apostrophe (U+2019) as U+FFFD (REPLACEMENT CHARACTER) — "owner�s phone" on the page, "owner's phone" in an otherwise word-for-word-verbatim quote. Not a model error; the byte was already lost upstream. Dropping apostrophe variants symmetrically on both sides closes that specific hole without weakening word-level matching.
Provenance of the _MD_BOLD carve-out. Same cat-cafe-monitoring smoke run (2026-07-20): Tavily's HTML-to-text for the Indoor positioning system Wikipedia page left literal markdown **bold** markers in otherwise-plain prose — "provide accuracy between **1-5 meters**" on the page, quoted without the **. Stripping ** symmetrically (same pattern as the apostrophe carve-out) closes that hole without weakening word-level matching.

verify_quote is the boolean form; quote_violation is the kind-aware form for callers that report why, not just whether. A quote that normalizes to empty is never grounded — "" in haystack would otherwise verify trivially — so quote_violation returns kind quote_empty (new in E-43); a missing match is quote_not_found. Note the split of responsibility: quote_violation only ever returns quote_empty or quote_not_found — it does not know whether the source exists. source_unavailable (was source_never_fetched) is emitted by the research wrapper below, which is what actually checks the page file is on disk.

def verify_brief(brief, run_id) -> list[Violation]:
    for f in brief.grounded_findings:
        page = pages_dir(run_id) / page_filename(f.source_url)
        if not page.is_file():
            violations.append(Violation(kind="source_unavailable",
                                        source=f.source_url, quote=f.quote))
            continue
        v = quote_violation(f.quote, page.read_text("utf-8"),
                            Profile.EXTRACTED_TEXT, source=f.source_url)
        if v is not None:
            violations.append(v)

Fail-and-continue semantics (E-29, 2026-07-20)

A non-empty violations list records the research stage as outcome=FAIL (judge="error", error string rejected:research.grounding: …) at feature.py:1804, but the run does not stop: brief_digest_val stays "" (retain + digest skipped) and everything after research proceeds on the idea alone, same as a research-disabled run. The verifier itself is unchanged — still byte-exact contiguous quotes, whitespace-normalized only; E-29 loosened the outcome, not the check. (This is not a ModelRetry: TemporalAgent silently drops @agent.output_validator — Task 1 finding A — so grounding is enforced as a post-run activity rather than an output validator.) Rubric judging of the brief runs only in the clean (else) branch, so a cell's research grade is earnable but not guaranteed.

Why verify_brief_activity returns rather than raises activity

temporalio's execute_activity wraps activity-raised exceptions in ActivityError(ApplicationError), which would prevent the workflow from catching a typed GroundingViolation. So the activity returns list[Violation] and the workflow inspects the result directly. A direct (non-activity) caller that prefers an exception interface can raise GroundingViolation(violations) from the returned list.

7. Memory contract leads, never grounded claims

def verified_findings_to_retain(brief, run_id, bank="project:default") -> list[RetainItem]:

Findings become leads, not grounded claims. A retained finding is a lead: a hint about where prior runs looked. On recall, the research agent sees them via recall_leads and must re-fetch to re-ground. This is enforced structurally, not by prompt: a recalled lead placed in grounded_findings fails source_unavailable by construction.

8. Two entry points, one agent stage vs mid-run

One core (the research agent); two callers. Both charge the same shared whole-run ceiling (max_run_cost_usd).

1. Top-level stage workflow

feature.py:1726 — runs once before clarify when cfg.research_enabled and t_research is not None. The workflow builds ResearchDeps, then fans out: plan_research → _fan_out_research (N × research_subquestion) → synthesize_brief, then verifies, gates (approve / reject / revise), retains, judges, records.

Each sub-question is its own Temporal activity; the agent inside runs in-process so its budget accumulates.

2. Architect mid-run agent

toolset.py:10 — research_subquery(deps, question) runs the same research agent on one sub-question. Imported lazily so agents/architect/agent.py stays importable without constructing the research agent at import time.

Runs inside the architect's tool-call activity — pydantic-ai's TemporalAgent cannot fan the inner agent's tool calls out as further activities from there, so it falls back to plain in-process execution and deps.budget genuinely accumulates here.

Both in-process paths degrade on budget exhaustion. Because each research_subquestion (stage) and research_subquery (architect) runs the agent in-process, a raised BudgetExceeded / UsageLimitExceeded is caught there and degrades to a brief with the shortfall recorded in gaps (matching ResearchConfig's documented contract) — never re-raised. The counter is persisted, so leaving it uncaught would escape the activity's Temporal boundary and retry into the same exhausted cap as an uncapped ApplicationFailure storm.

11. Known gotchas & accepted losses maintainer notes

1. @agent.output_validator is silently dropped by TemporalAgent

Task 1 finding A. Grounding is therefore enforced as a post-run activity (verify_brief_activity) rather than via an output validator. The workflow inspects the returned violations list and records the stage as FAIL — the run continues on the idea alone (E-29 fail-and-continue).

2. Budget was advisory-only under TemporalAgent — fixed by fan-out

Under the old single-t_research.run stage each tool activity received a fresh deserialised deps, so charge() never raised mid-run. The 2026-08-04 fan-out removed that hazard: research_subquestion runs the plain agent in-process (so deps.budget accumulates) and budget_store.py keeps persisted per-scope counters. The research_subquery (architect) path was always in-process and remains exempt.

3. read_repo must refuse by returning a string, never by raising

A raised ValueError on an out-of-root path becomes a Temporal ApplicationFailure retried with no cap — observed hanging a greenfield run indefinitely. Return "[refusing to read outside the repo root: …]" instead; the model reads it and moves on. Same pattern as the missing-file branch. The read_repo trigger is patched, but the broader hazard — any research tool raising a non-transient error loops the run with no attempt cap — remains open (E-28).

4. verify_brief_activity returns, does not raise

execute_activity wraps activity-raised exceptions in ActivityError(ApplicationError), which would prevent the workflow from catching a typed GroundingViolation. The activity returns list[Violation]; the workflow decides. GroundingViolation exists only for direct (non-activity) callers.

5. CodeMode was dropped 2026-07-17 — restored (scoped) 2026-07-29

The original design used CodeMode, then dropped it 2026-07-17 (untestable via TestModel under TemporalAgent). It is now back, scoped to the research agent only: ExaSearch (WrappedExaSearchToolset) + the Harness run_code capability are injected when provider == "exa", and the in-process fan-out path keeps them testable. The plain recall_leads / read_repo tools remain.

6. The stage is not memoized

A served memo would mean pages were not fetched this run, so a brief cannot be cached. Only the canonical brief_digest() feeds downstream content keys — the brief's prose is never part of the cache hash.

7. Recalled findings are LEADS, never grounded claims

Enforced structurally: verified_findings_to_retain() stores only verified findings as MemoryKind.RESEARCH_FINDING; a recalled lead placed in grounded_findings fails source_unavailable by construction. Re-fetch to promote.
